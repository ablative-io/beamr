# B-183: WITHDRAWN 21 Oct 2026: beamr's tests build offline on default features: the OpenTelemetry testing SDK is reached only through the telemetry feature

## Purpose

WITHDRAWN on 21 October 2026 at 06:13 (Melbourne), ruled by Waffles on Cambium (post 688d97db), kept on main so the next reader of the same premise sees why it is wrong. The premise below was Apollo's and the red at the base disproved it: at beamr main 14eb058d, 06:11, `cargo nextest run -p beamr --offline` refused with "failed to download `opentelemetry v0.32.0` ... --offline was specified", inside nextest's own `cargo metadata --format-version=1 --all-features --offline`; a plain `cargo metadata --offline` and `cargo tree -e normal,dev -p beamr --offline` refused the same way, and `cargo build -p beamr --lib --offline` built (13.7 s). Cargo's metadata and tree load the whole resolve, which needs the source of every package in Cargo.lock whether optional or not, and opentelemetry is already optional (Cargo.toml:35); only a compile fetches just what it builds. Moving opentelemetry_sdk behind a feature would leave both packages in the lock and every acceptance line below refusing. The remedy taken instead needs no code: the network window's first beamr act is `cargo fetch` in the checkout, putting every locked source on disk. Nothing below is to be built. The original purpose follows. Found on 21 October 2026 at about 06:05 (Melbourne) while B-181's lane built on Tom's Mac with no network: opentelemetry_sdk 0.32.1 is a plain dev-dependency of crates/beamr (Cargo.toml:78 at beamr main dc88b857, with its `testing` feature, under [dev-dependencies] at :49), so every test build of the crate compiles it, whatever features are selected. Yet every use of it is test code of the optional telemetry feature (telemetry = ["std", "dep:opentelemetry"], :125): the unit tests in src/telemetry/spans.rs (mod tests, :296-), src/telemetry/lifecycle_tests.rs (included under #[cfg(test)] at lifecycle.rs:333-334) and the #[cfg(feature = "telemetry")] items of src/scheduler/tests.rs (:10-17 and 22 cfg sites). With the crate not on disk and no download allowed, no beamr test of any feature set can build, so the whole suite waited on a network window for a dependency that only telemetry's tests use. Waffles ruled at 06:05 (Cambium post c92ad3e1) that this is a beamr row of its own, named today. Cargo cannot make a dev-dependency optional, so the SDK moves to where only the telemetry tests reach it.

## Task

Make opentelemetry_sdk an optional dependency of crates/beamr enabled only by a new telemetry-testing feature that implies telemetry, put every test that uses it under that feature, and remove it from [dev-dependencies]; crates/beamr/Cargo.toml, src/telemetry/spans.rs, src/telemetry/lifecycle.rs and lifecycle_tests.rs, src/scheduler/tests.rs. The release battery and the gate's --all-features legs select it as they select telemetry today; the CHANGELOG says so.

## Requirements

### R1: A default-features test build of beamr needs no OpenTelemetry crate

Behavioural. THE SYSTEM SHALL remove opentelemetry_sdk from crates/beamr's [dev-dependencies] and declare it as an optional dependency with its `testing` feature, enabled only by a new feature telemetry-testing = ["telemetry", "dep:opentelemetry_sdk"]; every test, test module and test helper that names opentelemetry_sdk (src/telemetry/spans.rs's tests, src/telemetry/lifecycle_tests.rs, the telemetry items of src/scheduler/tests.rs) SHALL compile only under cfg(all(test, feature = "telemetry-testing")). No non-test code SHALL name opentelemetry_sdk. The feature's comment SHALL say it exists only so the telemetry tests can reach the SDK's in-memory exporters, and that it is for tests, not embedders. Every cfg that names telemetry-testing SHALL be of the form cfg(all(test, ...)), so an embedder who turns the feature on gets the SDK compiled and nothing else, shown by a search of the workspace quoted in the handback.
