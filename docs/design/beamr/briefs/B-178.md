# B-178: Empty-bundle class — no public entry point may default the native surface

> **Cluster:** beamr
> **Measured at:** `48a12a594bd5e88c19d7f5fb47c9458462220293` (`origin/main`). Every
> coordinate below was re-opened at this tree; the ground pack this brief consumes
> (`GROUND-PACK-86.md`, untracked at the worktree root) was measured at `cd05573`,
> and the two trees differ in files this brief does not touch. Where the ground
> pack and this tree disagree, **this brief's number is the one measured here**
> and the disagreement is recorded in *Census errata*.
> **Release:** `0.18.0` (breaking).

## Purpose

**No public construction or execution entry point may DEFAULT the native surface**
— neither the BIF registry nor the `NativeServices` bundle. "No natives" stays a
legitimate configuration: four shipped downstream production consumers use it
(haematite `db/startup.rs:343`, liminal `conversation/actor.rs:289`, liminal
`channel/supervisor.rs:152`, liminal-server `connection/supervisor.rs:1091`). What
ends is the *implicit substitution*: from `0.18.0` the emptiness is a value the
call site wrote down.

The class has twenty public members across four families; twelve substitute an
empty bundle silently. It has already cost two multi-seat incidents (2026-07-18
being the sanctioned one), it is already documented in three long rustdoc footgun
sections, and a downstream consumer has already shipped a wrapper
(`frame_core::composition::compose_scheduler`) to route around it. **Documentation
was tried and the second incident still happened.** This brief makes the wrong
composition unrepresentable rather than better-explained.

`WasmScheduler::new` (`crates/beamr/src/scheduler/wasm.rs:166`) already takes
`bif_registry: Arc<BifRegistryImpl>` as a required parameter. It is the in-tree
prior art for the shape this brief generalises, and **it is not touched**.

## Task

Re-signature Family A (four `Scheduler` constructors) onto a new declared-natives
type; delete the three zero-value interpreter rungs and keep one entry point;
thread an explicit `services` argument through the two defaulting opcode
dispatchers and delete the zero-caller third; add a required `services` parameter
to both `ReplayDebugger` constructors; re-aim the guard-BIF refusal from the
executing module at the construction site — **falsifier committed first**; sweep
the docs; bump to `0.18.0` with a migration-mapped CHANGELOG.

226 in-tree call sites migrate. Nothing is published, tagged, or pushed.

## Decisions

Where the frozen design left a choice, it is made here. Each is overridable by the
coordinator; none is silent.

### D1 — The declared-natives type is named `NativeBifs`

**Ruling: keep the working name.** `NativeBifs` names the **value** — the native
BIFs this scheduler resolves — and reads correctly at both call sites it will ever
have: `NativeBifs::none()` and `NativeBifs::registry(bifs)`.

Rejected alternatives, with the reason each fails: `DeclaredNatives` puts the
declaration in the *type*, but the declaration is the **act of passing it**, not a
property of the value — a `DeclaredNatives` stored in a struct field is no longer
declaring anything, and the name would go quietly false. `BifRegistryChoice` and
`BifRegistryOption` name the mechanism rather than the value, and both would render
`::none()` as "no **registry**" — which is precisely the reading P5 forbids,
because the three-way registry state (absent / wired-empty / wired-populated) is
the trap this whole brief is navigating; a name that teaches "none means no
registry" would seed the next mis-attribution. `NativeBifSet` implies a
collection with a cardinality, and **no emptiness predicate exists on
`BifRegistry`** (measured: `native/mod.rs` exposes `lookup` only), so a name
promising set semantics would promise an answer the type cannot give.

`NativeBifs::none()` is also the string the refusal text will name, so the type
name is load-bearing in an error message, not only in a signature.

### D2 — `NativeBifs` lives in `crates/beamr/src/scheduler/services.rs`

Co-located with `SchedulerServices`, its sibling declared-composition type
(`minimal()` / `full_runtime()` / `from_config()` is the same idiom), re-exported
through the existing `pub use services::{...}` line at `scheduler/mod.rs:155` under
the same `#[cfg(feature = "threads")]` gate the four constructors already carry.
No new module: `services.rs` is 505 lines and the addition is ~60.

### D3 — The declared-natives argument goes LAST in all four Family-A signatures

Every existing call site becomes a pure **append**: no argument reordering, so the
migration diff is mechanically reviewable and a mis-ordered call is a type error
rather than a silent swap. Same rule for `dispatch` / `dispatch_with_receiver`
(D6) and for both `ReplayDebugger` constructors (D8), so one rule covers the
whole brief.

### D4 — `NativeBifs` is a newtype over `Arc<BifRegistryImpl>`, not an enum

`construct_with_services` (the single terminal choke point, `scheduler/mod.rs:1302`)
takes `bif_registry: Arc<BifRegistryImpl>` — non-optional. So `NativeBifs` must
yield one. `none()` mints `Arc::new(BifRegistryImpl::new())` **inside the
constructor**: the three scattered mint literals at `:1070`, `:1148` and `:1296`
collapse into one site that a caller had to ask for by name. The mint does not
disappear; it stops being a default.

### D5 — `NativeBifs` derives `Clone`; `Debug` is written by hand

`Clone` because `Arc` makes it free and multi-scheduler tests construct several.
`Debug` by hand, emitting `NativeBifs { .. }`: `BifRegistryImpl` derives `Debug`
over a `DashMap` of every registered MFA, so a derived `Debug` would dump the whole
BIF table into any formatted diagnostic that happened to include one. No `Default`,
no `From<()>`, no `From<Arc<BifRegistryImpl>>` — construction must be typed at the
call site (P1).

### D6 — `dispatch` / `dispatch_with_receiver` take `services` LAST, and derive the WHOLE `DispatchCtx` from it

The new parameter is not wired into `DispatchCtx.services` alone. When it is
`Some(services)`, `timers`, `atom_table`, `jit_cache` and `jit_profiling` are
derived from it **exactly as `dispatch_with_services` derives them**; when it is
`None`, all five stay `None`. Anything less would give `dispatch(.., Some(s))` a
different runtime context from `dispatch_with_services(.., s, ..)` with the same
`s` — a new trap of the same family as the one being removed.

Ordering: `services` last, after `registry`, rather than before it to mirror
`dispatch_with_services`. Cosmetic symmetry with a function whose `services` is a
different type (`&NativeServices`, non-optional) is not worth inserting an argument
into the middle of 13 call sites.

`dispatch_with_services` keeps its signature and behaviour. Its body **may** be
reduced to `dispatch_with_receiver(process, module, instruction, next_ip, None,
registry, Some(services))` — permitted, not required, and only if the resulting
`DispatchCtx` is field-for-field identical to today's.

### D7 — Test files migrating off `interpreter::run` may add VALUE helpers, never DOOR helpers

**PERMITTED:** a file-local helper returning a value the call site still names in
its argument list — `fn empty_native_services() -> NativeServices` (one already
exists at `interpreter/tests.rs:78`), `fn empty_module_registry() -> ModuleRegistry`.

**FORBIDDEN:** any file-local helper that wraps the entry point — e.g.
`fn run(process: &mut Process, module: &Module)`. That would reintroduce the
deleted door at test scope, and the deletion would have bought nothing. This is a
hard gate with its own acceptance criterion (R5).

### D8 — `ReplayDebugger`'s `empty_native_services()` helper is deleted

`crates/beamr/src/replay/debugger.rs:487-489` exists solely to feed the constructor
at `:160`. Once `services` is a parameter the helper has no caller, and leaving a
dead private fn fails `-D warnings`. The four in-file test callers pass
`NativeServices::default()` explicitly — which is the declaration P4 asks for.

### D9 — The attribution field is a three-state enum describing the RUNTIME context, and it asserts nothing about emptiness

`GuardBifUnavailable` gains one field, `runtime_natives: RuntimeBifRegistryState`,
a new `Copy` enum in `error.rs` alongside `GuardBifResolution`, with three arms
that are each true **by construction** at the mint point (`guards.rs:168`, inside
`pub fn bif` which holds `services: Option<&NativeServices>`):

| arm | condition at the mint point | what it asserts |
|---|---|---|
| `Absent` | `services` is `None` | no native services bundle reached this dispatch |
| `Unwired` | `services` is `Some`, `bif_registry` is `None` | the bundle carried no BIF registry |
| `Wired` | `services` is `Some`, `bif_registry` is `Some` | a BIF registry was wired |

`Wired` deliberately says **wired**, not **populated** — no emptiness predicate
exists on `BifRegistry` to make the stronger claim, and the loader-time and
runtime registries are different objects with no provenance on
`Module`/`ResolvedImport`. Everything beyond these three facts ships as a static
POINTER, never as a claim about the caller's registry.

**Measured: `Wired` is the value on EVERY production execution path — including
the exact composition this brief exists to attribute.** `build_native_services`
(`scheduler/supervision_integration.rs:545`) sets
`bif_registry: Some(Arc::clone(&shared.bif_registry))` **unconditionally** at
`:678`, and `SharedState::bif_registry` (`scheduler/mod.rs:351`) is a
non-optional `Arc<BifRegistryImpl>`. That builder is the sole services source for
every interpreter entry on the scheduler path (`execution/core.rs:671`, `:1492`,
`execution/native_slice.rs:66`, `:226`, `:277`,
`module_management/helpers.rs:132`), and `scheduler/wasm.rs:805` does the same
for `WasmScheduler`. So a `Scheduler::new` built on an empty minted registry
reports `Wired`, identically to a correctly-composed gate1 scheduler — and after
R2 a scheduler declared `NativeBifs::none()` reports `Wired` too, because
`none()` mints an empty registry and that registry is then wired (D4). `Absent`
requires `services == None`, reachable only from `opcodes::dispatch` /
`dispatch_with_receiver`, whose 13 call sites are all `#[cfg(test)]`
(*Census — Family C*); `Unwired` requires a `NativeServices::default()`,
reachable only from `ReplayDebugger`, which has zero non-test callers
(*Census — Family D*).

**Three consequences, all binding:**

1. **The field is not the attribution — the static POINTER is.** The field is
   kept regardless: after R6 a caller CAN pass `None` services at the opcode
   seam, the three states are the only facts true by construction at the mint
   point, and a field costs less than the alternative (below). But no part of
   this brief may lean on it to discriminate a real composition defect, because
   on every path that has ever produced an incident it renders the same word.
2. **`Wired` SHALL NOT be allowed to read as exculpatory.** Rendered alone, "a
   BIF registry was wired" reads as absolution in precisely the scenario where
   the registry is the fault. The rendered line therefore pairs it with the fact
   that makes it non-exculpatory — that a `NativeBifs::none()` scheduler also
   reports `Wired` — which is true by construction (D4), states a property of
   the constructor rather than of the caller's registry, and accuses nobody.
   R10 carries the exact string.
3. **R10's acceptance SHALL NOT read three green arms as production coverage.**
   Two of the three states are reachable only through test-only seams; that is
   measured above and R10 records it as a limitation rather than letting a
   three-arm test stand as evidence the field discriminates where it would
   actually be read.

A FIELD, not a variant: a new `ExecError` variant would break
`beamr-wasm/src/reasons.rs:50-71`, which matches `ExecError` exhaustively with no
`_` arm, and the fix would be a cross-crate edit or a banned `_` arm. **The five
in-tree matchers are NOT uniformly `{ .. }` — measured at `48a12a5`:** three are
source-compatible and need no edit (`beamr-wasm/src/reasons.rs:69` `{ .. }`,
`tests/composition_report.rs:94` `{ resolution, .. }`,
`tests/guard_bif_unavailable.rs:97` `{ arity, resolution, .. }`); two are **not**
(`error.rs:262` and `error.rs:315` each destructure
`{ module, function, arity, resolution }` exhaustively with no `..`, and will
fail to compile until they bind the new field). Those two are the `Display` and
`format_with_atoms` arms that R10 edits anyway to render the new state, so the
field costs two edits that were already required and zero edits outside this
crate — which is the actual argument for the field, and it survives. **The
earlier form of this sentence claimed all five used `{ .. }`; it was inherited
verbatim from the frozen design and is false.** A reviewer reading it would
conclude "source-compatible, no matcher edits" and the change would not build.
R10 (`:653` region) states the required action.

### D10 — `GuardBifResolution::Deferred`'s hint is amended to name WHICH registry

Today: `"native BIF registry has no entry and the target module is not loaded"`.
That sentence is true of the **loader-time** registry, and in the divergence case
it will sit one clause away from `runtime natives: Wired` and read as a
contradiction. Amended to:
`"the LOAD-TIME native BIF registry had no entry and the target module is not loaded"`.
Still `pub const fn -> &'static str`, still static. This forces the byte-exact
pins in `tests/guard_bif_unavailable.rs:32-41` to move, which they must anyway.

### D11 — Version-ref scope: dependency pins move, dependent crate versions do not

`crates/beamr/Cargo.toml:3` `0.17.0 → 0.18.0`; `crates/beamr-cli/Cargo.toml:16`
and `crates/beamr-wasm/Cargo.toml:18` both pin `beamr = { version = "0.17.0",
path = ... }` and **must** move to `"0.18.0"` — a path dependency whose version
requirement does not match the path crate's version fails to resolve, so this is a
build requirement, not a style choice. `Cargo.lock` updates as a side effect and is
tracked. `beamr-cli`'s own `0.5.0` and `beamr-wasm`'s own `0.8.0` are **not**
bumped here: neither crate has a source change (measured — `Scheduler::new` /
`::with_services` / `interpreter::run*` return zero hits in `crates/beamr-cli/src`
and `crates/beamr-wasm/src`), and dependent-crate version policy belongs to the
release cut, which this brief explicitly does not perform. `probes/lane-62/Cargo.toml:22`
depends by path with no version and needs no edit; the two `docs/.../repro/*/Cargo.toml`
pins (`=0.16.0`, `=0.16.2`) are frozen evidence artifacts and must not be touched.

### D12 — The `guard_bif_unavailable.rs` wall's green arm is rebuilt, not re-pointed

`start_scheduler` (`:48-60`) hands `bifs` to `load_module` at `:50` and then builds
the scheduler with `Scheduler::new` at `:51`, which mints its own empty registry.
**Both arms therefore run on an empty scheduler registry today**; the green arm
passes on load-time resolution, not on the composition its name claims. R2 forces
that call site to declare, and the only honest declaration differs per arm:
`NativeBifs::none()` for the refusal arm, `NativeBifs::registry(...)` — the same
`Arc` the loader saw — for the clean arm. This is a consequence of R2, not an
extra: there is no way to satisfy R2 at that call site *and* leave the arms
identical without writing a declaration the test's own name contradicts.

## Requirements

### R1: `NativeBifs` — the declared-natives type

`crates/beamr/src/scheduler/services.rs` SHALL define a public `NativeBifs` type
with exactly two constructors and no other public construction path. It SHALL be
re-exported from `crates/beamr/src/scheduler/mod.rs` in the existing
`#[cfg(feature = "threads")] pub use services::{...}` item at `:155`.

Final public surface:

```rust
/// The native BIF surface a scheduler is DECLARED with at construction.
///
/// Every public `Scheduler` constructor takes one of these by value. There is no
/// `Default` and no `From` conversion, so "this scheduler resolves no native
/// BIFs" is a value the call site had to write down rather than a default it
/// inherited.
#[derive(Clone)]
pub struct NativeBifs { /* private: Arc<BifRegistryImpl> */ }

impl NativeBifs {
    /// Declare that this scheduler resolves NO native BIFs.
    ///
    /// `erlang:*` imports will refuse at guard-BIF execution: every
    /// erlc-compiled module imports `erlang:*` (`module_info` alone imports
    /// `erlang:get_module_info`), those imports resolve non-native, and the
    /// first arithmetic, comparison or type guard raises a process-fatal
    /// [`ExecError::GuardBifUnavailable`](crate::error::ExecError). This is a
    /// legitimate configuration for a scheduler that runs only native actors and
    /// loads no bytecode; it is a defect for any scheduler that loads a `.beam`.
    #[must_use]
    pub fn none() -> Self;

    /// Declare `registry` as this scheduler's native BIF surface.
    ///
    /// Apply at least
    /// [`register_gate1_bifs`](crate::native::bifs::register_gate1_bifs) before
    /// constructing, and hand the SAME `Arc` to
    /// [`load_module`](crate::loader::load_module): imports bind at LOAD time
    /// against the loader's registry, so a scheduler carrying a different
    /// registry object does not repair a load performed against an empty one.
    #[must_use]
    pub const fn registry(registry: Arc<BifRegistryImpl>) -> Self;
}

impl std::fmt::Debug for NativeBifs { /* writes "NativeBifs { .. }" */ }
```

A crate-private accessor (e.g. `pub(crate) fn into_registry(self) -> Arc<BifRegistryImpl>`)
carries the value to `construct_with_services`.

**Acceptance:**
- `NativeBifs` has exactly two public constructors, `none()` and `registry(_)`
- **No `Default` reaches `NativeBifs` by ANY route, including a derive.** The
  one-token slip `#[derive(Clone, Default)]` produces a working
  `NativeBifs::default()` — an empty registry conjured with no call-site
  declaration, i.e. exactly P0's sin restored at the new type — and it is
  measurably constructible, not hypothetical: `BifRegistryImpl` is
  `#[derive(Debug, Default)]` (`native/mod.rs:329`), so
  `Arc<BifRegistryImpl>: Default` and the derive compiles. An
  `impl Default`-shaped grep is blind to it. Three gates, not one:
  - `rg -n "impl Default for NativeBifs|impl From<.*> for NativeBifs" crates/` returns rc=1
  - `rg -n --multiline "#\[derive\(Clone\)\]\npub struct NativeBifs" crates/beamr/src/scheduler/services.rs`
    returns rc=0 — the derive list is pinned to exactly `Clone`, so ANY addition
    to it (`Default` included) fails this gate. The doc comment sits above the
    derive, per the sketch, so the two lines are adjacent.
  - `rg -n "NativeBifs::default\(\)" crates/` returns rc=1 — nothing can name it
- The `Debug` impl does not format the registry contents (no `DashMap` walk)
- `NativeBifs::none()`'s doc comment states the refusal consequence in the terms above
- `NativeBifs` is reachable as `beamr::scheduler::NativeBifs`

**Files:**
- modify: `crates/beamr/src/scheduler/services.rs`
- modify: `crates/beamr/src/scheduler/mod.rs`

### R5: Family B — migrate all 80 call sites and 9 import lines

Every site listed in *Census — Family B* SHALL move to `run_with_native_services`
with both arguments written explicitly at the call site.

Migration mapping:

| from | to |
|---|---|
| `run(p, m)` | `run_with_native_services(p, m, &ModuleRegistry::new(), &NativeServices::default())` |
| `run_with_registry(p, m, &r)` | `run_with_native_services(p, m, &r, &NativeServices::default())` |
| `run_with_timer_services(..)` | *(no call sites — deleted outright)* |

**The `run` mapping is behaviour-preserving, and the argument is NOT "nothing
branches on the Option".** `run` passes `None` for the registry; the replacement
passes `Some(&empty)`. Almost every consumption of that `Option` in the
interpreter is `.and_then(|r| r.lookup(..))` (`interpreter/mod.rs:255-256`,
`opcodes/core.rs:545`, `:584`, `opcodes/closures.rs:89`, `:256`, and
pass-throughs at `opcodes/mod.rs:219/236/243/256/278/413/430`,

```markdown
## 0.18.0 — <YYYY-MM-DD of the landing commit>

Minor release, cut from `main`. **Breaking, deliberately.** Twelve public
entry points across four families silently substituted an empty native
surface — an empty `BifRegistryImpl`, or a `NativeServices::default()`, or
both — when the caller did not supply one. That default cost two multi-seat
attributions (the 2026-07-18 gc_bif incident is the sanctioned one), was
already described in three long rustdoc footgun sections, and had already
provoked a downstream wrapper (`frame_core::composition::compose_scheduler`)
built specifically to route around it. **Documentation was tried, a
downstream workaround was tried, and the second incident still happened.**

**"No natives" remains a supported configuration.** Four shipped production
consumers use it, and nothing here takes it away. What changes is that it is
now a value you write down: `NativeBifs::none()` at the call site, not an
empty registry conjured by a constructor that did not mention one. The sin
was the default, not the emptiness.

The error the wrong composition produces changes with it. `GuardBifUnavailable`
used to name the module that was executing — which is never the module at
fault — and its hint said "native BIF registry has no entry" without saying
*which* registry, of which there are two: the one the loader resolved imports
against, and the one the scheduler carries. It now reports which of the two
was reachable at the refusal, and points at construction rather than at the
executing module. It still does not claim your registry is empty, because
`BifRegistry` exposes no emptiness predicate and the two registries can
legitimately disagree — a claim we cannot substantiate is how the first
incident accused an innocent component, and we are not repeating it in a new
direction.

### Removed (breaking)

- **`interpreter::run`** — executed with `NativeServices::default()` and no
  module registry. Migrate to
  `run_with_native_services(process, module, &ModuleRegistry::new(), &NativeServices::default())`;
  the substitution is behaviour-identical (every consumption of the optional
  registry is `.and_then(|r| r.lookup(..))`, so an empty registry and no
  registry are indistinguishable).
- **`interpreter::run_with_registry`** — carried a module registry and
  defaulted the services. Migrate to
  `run_with_native_services(process, module, registry, &NativeServices::default())`.
- **`interpreter::run_with_timer_services`** — filled one of `NativeServices`'
  34 fields and nulled the registry. Zero callers estate-wide at removal.
  Migrate to `run_with_native_services` with a `NativeServices` carrying your
  `timers`.
- **`interpreter::opcodes::dispatch_with_timer_services`** — same shape at the
  opcode seam. Zero callers estate-wide at removal. Migrate to
  `dispatch_with_services`.

`interpreter::run_with_native_services` is unchanged and is now the single
interpreter entry point.

### Changed (breaking)

- **`Scheduler::new(config, module_registry)` → `Scheduler::new(config, module_registry, natives)`.**
  Pass `NativeBifs::registry(bifs)` to keep executing bytecode, or
  `NativeBifs::none()` to declare that this scheduler resolves no natives.
- **`Scheduler::with_services(config, services, module_registry)` → `(config, services, module_registry, natives)`.**
  Same mapping. Note that this constructor's own docs used to redirect
  embedders *here* from `Scheduler::new`, and it defaulted the registry too —
  the prescribed migration target was itself in the defect class. It is no
  longer, and the redirect now points at `with_services_and_code_server`.
- **`Scheduler::new_replay(config, log)` → `(config, log, natives)`.**
- **`Scheduler::new_replay_with_registry(config, module_registry, log)` → `(config, module_registry, log, natives)`.**
  The "registry" this constructor names was always the MODULE registry; the
  fourth argument is the native one.
- **`ReplayDebugger::new(process, module)` → `(process, module, services)`** and
  **`ReplayDebugger::with_snapshot_granularity(process, module, granularity)` → `(process, module, granularity, services)`.**
  Pass `NativeServices::default()` for the previous behaviour. The builders
  `with_registry` and `with_native_services` are unchanged and still override.
- **`opcodes::dispatch(.., registry)` → `dispatch(.., registry, services)`** and
  **`opcodes::dispatch_with_receiver(.., receiver, registry)` → `(.., receiver, registry, services)`.**
  Pass `None` for the previous behaviour. `Some(&services)` now behaves exactly
  as `dispatch_with_services` does with the same bundle.
- **`ExecError::GuardBifUnavailable` gains a `runtime_natives` field**
  (`RuntimeBifRegistryState::{Absent, Unwired, Wired}`). Matchers using
  `{ .. }` are unaffected; exhaustive field destructuring needs the new name.
  A field rather than a new `ExecError` variant, so exhaustive `ExecError`
  matches (e.g. `beamr-wasm`'s reason mapper) keep compiling.

Constructors NOT changed: `Scheduler::with_services_and_code_server`,
`Scheduler::replay_with_services_and_code_server`, `Scheduler::with_code_server`,
`Scheduler::with_code_server_and_policy`, `WasmScheduler::new`,
`opcodes::dispatch_with_services`, `interpreter::run_with_native_services`.
All of them already required the caller to supply the native surface; they are
the shape the rest has been moved onto.

### Changed

- **The guard-BIF refusal points at construction instead of accusing the
  executing module.** `GuardBifUnavailable` now renders which of the three
  runtime registry states applied (`Absent` — no services bundle reached the
  dispatch; `Unwired` — a bundle with no registry; `Wired` — a registry was
  present) and carries a fixed pointer naming the constructor family. It does
  NOT assert that your registry is empty: imports bind at LOAD time against the
  loader's registry, `Module`/`ResolvedImport` record no provenance, and the two
  registries can differ, so that assertion could accuse a correctly-composed
  caller. The `Deferred` hint now says "the LOAD-TIME native BIF registry",
  naming which of the two it means. Note what `Wired` does and does not tell
  you: a scheduler declared `NativeBifs::none()` reports `Wired` too, because
  `none()` wires an empty registry. On the scheduler path `Wired` is the value
  you will almost always see; the discriminating information is the pointer, not
  the state.
```
