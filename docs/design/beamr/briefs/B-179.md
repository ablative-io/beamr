# B-179 — Terminal admission and post-removal completion

## Purpose

A stopped scheduler can accept work that cannot receive a reply, and an early exit record cannot prove process-table removal. Close these two gaps in beamr so Haematite and liminal can await owned signals. This brief orders implementation and qualification; it does not claim either defect fixed.

## Existing costs and ownership

The published enqueue path obtains a body-map reference and slot mutex, checks a tombstone, then pushes an atom or defers into Executing metadata. Successful atom delivery calls wake_process, which checks suspension state, obtains the wait-set mutex, and may notify workers. Host-owned Executing delivery waits on its completion channel after dropping the slot/map reference. Exact dynamic lock/map/atomic/clone/copy/allocation/wake counts and physical sync totals are not measured here; both requirements must qualify the complete live-message vector.

Finalization uses table removal as its winning token. Body removal/resource release has separate ownership; a worker may later dispose its Executing body. The finalizer also takes wait-set and pg-registry locks. Existing outcome/event/watch publication precedes removal. Completion follows successful table removal with its guard released, consumes no outcome, and calls no user callback under a lock. No disk sync or stored shape is proposed. A whole-state clone or history traversal is forbidden.

## Requirements

### R1 — Refuse terminal-process admission and settle abandoned work

WHEN scheduler shutdown has returned or a target process reaches its irreversible terminal boundary, THE SYSTEM SHALL refuse enqueue_atom_message with false through its existing surface. WHEN an accepted request races that boundary, THE SYSTEM SHALL execute it before termination or release the scheduler-owned queued request and its reply sender before terminal completion returns. WHILE a waiting, suspended, or executing process remains resumable, THE SYSTEM SHALL preserve admission and wake behavior. THE SYSTEM SHALL NOT add work to the steady live-message path. R1 spawn amendment: reserve the existing teardown admission before direct bytecode process publication and retain the reservation through publication. Refusal returns ExecError::SchedulerTerminated before allocating a pid, inserting a process body/table entry, or recording any tombstone. Shutdown closes admission and waits for racing publishers; a bare shutdown atomic is insufficient.

Acceptance:

1. Behavioral red on published beamr 0.20.0 at 05adf473333ddafdc85691634c14a49d60abc8c0: spawn a native process whose ready channel proves it reached NativeOutcome::Wait; keep scheduler and process handle alive; call scheduler.shutdown and join that owned stop; assert enqueue_atom_message(pid, marker) == false. Published code accepts the retained Present body after its worker has joined. Failure must be this boolean assertion, not an unresolved symbol, compiler error, timeout, or deliberately hung receiver.

2. Use an embedder-shaped owned command queue whose Shutdown command owns the last reply sender. After the readiness handshake and joined shutdown, queue that command, attempt enqueue, and handle false by dropping the exact command. Assert the reply receiver is disconnected using try_recv and the command was not executed, while queue and scheduler remain alive. List every sender clone; drop deliberate extras before the disconnection assertion. beamr cannot close a sender independently owned by an embedder.

3. Coordinate accepted-before-close, admission-contending-with-close, and rejected-after-close cases with barriers/channels at the actual admission and finalization boundaries. For each command ID assert exactly one executed reply or explicit rejection/drop, no duplicate execution, no retained scheduler-owned request/completion sender after stop, and executed + dropped == submitted. An abandoned HostOwned mailbox completion settles through the existing typed terminal error. Record observations, release barriers, join workers, and clean up before evaluating a red assertion.

4. Keep positive cases for ordinary receive, Executing-slot deferred delivery, and result-gated suspension. A parked process is not terminal. Preserve existing bool and MailboxSendError interfaces, OwnedTerm ownership, message order, and shutdown service ownership. A check outside slot ownership must not create a check-then-enqueue race.

5. Run N=128 and N=256 live-message workloads separately for Present, Executing, and result-gated-suspended targets, with identical worker count, payload, preallocation, and release signals on published baseline and candidate. Count actual map/table probes, slot/wait-set lock acquisitions, lifecycle/admission atomic reads, heap/message allocations, term copies, mailbox pushes, wake calls/notifications, and whole-state clones at call sites. Assert each candidate component per N <= its measured published baseline and delivered == N after resumption. Do not hide a new per-message lifecycle check in an uncounted helper. Report full before/after vectors and N; no counts were measured in this authoring box.

6. Place any necessary extra work on the one terminal transition under existing admission ownership instead of new per-message polling, callbacks, history scans, or locks. Count cleanup visits/released requests separately; bound them by currently owned processes/queued requests, not all historical pids. Introduce no per-message disk sync or downstream copied runtime.

7. After joined shutdown, direct bytecode spawning and trap-exit spawning return ExecError::SchedulerTerminated. Observe unchanged next_pid, no new process-table/body entry and no new tombstone. Also rendezvous a publisher holding the existing admission reservation against shutdown: close waits until publication completes, and terminal cleanup leaves no admitting body. The published behavioral red uses the existing spawn surface and records a returned pid/admitting body before cleanup; the new error surface is candidate-only, and a missing symbol or exhaustive-match compiler error is never a red. No minted pid with a Normal tombstone stands in for refusal.

8. Change enqueue_spawn_with_trap_exit and its two private wrappers to Result<u64, ExecError>, propagating through the existing Result-returning public spawn entrypoints; both test-support scaffolds return Result too. Document SchedulerTerminated in error.rs and its Display mapping. ExecError is exhaustive, so CHANGELOG names the breaking variant and scaffold return change. Caller Result handling and exhaustive matches require their separately owned follow-up, with explicit variant arms rather than a wildcard bypass. Existing bool and MailboxSendError surfaces remain.

### R2 — Observe process-table removal without telemetry

WHEN the winning finalizer removes a process from process_table, THE SYSTEM SHALL offer an additive notification-only one-shot completion watch whose successful answer proves that removal. Registration SHALL answer Live(watch), AlreadyRemoved(pid, reason), or NoRecord. A still-present process with an early exit record SHALL remain Live. Fire SHALL follow successful table removal and release of its map guard, outside telemetry. Existing outcome installation, exclusive exit-event ordering, watch_exit behavior, and exactly-once outcome consumption SHALL remain.

Acceptance:

1. Behavioral red on published 0.20.0: hold an owned test-only rendezvous after exit-record installation but before process_table.remove. The existing install_event_publication_gate holds publication after its send; use a blocking channel-based test accessor compiled identically for baseline and candidate instead of its timed helper. While held, assert process_table.get(pid).is_some(), register the published watch_exit adapter, and record AlreadyExited. Release, join, and clear the fixture before asserting that an immediate completion answer must imply table absence. Published code fails that assertion because its record precedes removal. A missing proposed API is not a red.

2. Provide one additive scheduler registration surface (proposed name watch_exit_completion) with typed Live/AlreadyRemoved/NoRecord answers and a one-shot receiver. Arm before checking removal, then recheck with ordering that closes registration-versus-removal and lookup-versus-publication races. A tombstone alone never proves removal. Unknown pid returns NoRecord and retains no watch.

3. Repeat the held-gap case using completion registration before exit and during the early-record gap: both remain pending while process_table.get(pid) is Some, proven by nonblocking observation at the rendezvous. Release; await the real completion channel; assert exact pid/reason and table absence; join the finalizer. After removal, registration answers AlreadyRemoved immediately. Exercise all three positions and concurrent winning/losing finalizers using signals. No sleeps, clock polling, raised timeouts, skipped assertions, or serial markers.

4. Existing watch_exit retains its early-record contract and subscribe_exit_events keeps its one-per-scheduler-lifetime stream, outcome-before-event ordering, and Lagged behavior. A completion observer never calls take_exit_outcome or claims the stream. With multiple completion watches, assert the existing outcome owner can still take exactly one outcome. After outcome consumption and bounded tombstone eviction, AlreadyRemoved still reports pid/reason using the existing authoritative retained record; do not create another permanent historical pid ledger.

5. Only the winning table-removal token fires completion once per watch. Duplicate cleanup, watcher drop, and receiver disconnection retain no slots and run no user callbacks under internal locks. Drop deregisters; fire removes slots; registration counts return to their starting value after every scenario. The guarantee is table absence, not completion of the separately owned resource-release path for an Executing body.

6. Run completion tests without and with telemetry, and each threaded/cooperative configuration supporting this API. Preserve existing exit-observation, supervision, service ownership, and mailbox assertions. Repeat R1 N=128/256 vectors with 0 and 128 completion watches on unrelated pids: each per-message component stays <= published baseline. Separately count exit-watch lookups/sends, bounded by watches for this pid without scanning all watchers or process history. Report complete vectors; runtime reds/greens/counts are not measured in this authoring box.
