## Purpose

Give every beamr pid issuer one bounded monotonic contract, so an old process identity cannot become a different process and exhaustion is a named refusal rather than wrap, saturation or arbitrary registration. This brief defines later implementation and qualification; it does not claim a runtime fix.

## R1 — Use one bounded monotonic allocator per runtime ownership domain

WHEN any process identifier is requested, THE SYSTEM SHALL reserve it through one allocator authority shared by that runtime domain and its process table. The greatest issuable identifier SHALL be Term::PID_MAX. Identifiers SHALL increase and SHALL never recycle during the allocator lifetime. Once exhausted, the allocator SHALL stay exhausted and return a named refusal before publication. Production SHALL NOT reset, reseed, wrap, saturate, scan history, or infer availability from tombstone eviction.

Checklist: C36, C57

Stories: S15

Acceptance:

1. A test-only fixture seeds the real allocator at M-1, where M=Term::PID_MAX. Three reservation attempts yield exactly M-1, M, and PidSpaceExhausted: 2 successful reservations, 1 refusal, 2 distinct identifiers, and no identifier above M. Sixteen further attempts yield 16 identical named refusals, 0 successful reservations, and unchanged exhausted state.
2. Keep the existing runtime-specific reserved identifiers and starting points explicit. The standalone table currently starts at 0 (registry.rs:46); threaded and cooperative schedulers start at 1 (scheduler/mod.rs:1629, wasm.rs:186). Standard-IO identifier initialization is registered exactly once through allocator authority; ordinary issuance cannot collide with it. No new placeholder identifier is introduced.
3. Concurrent publishers rendezvous with only one identifier left. Exactly one reserves M and every loser gets PidSpaceExhausted. Record attempts, successful reservations, refusals and commits; successes+refusals=attempts, successful commits<=successful reservations, and duplicate identifiers=0. Coordinate with barriers/channels, then release and join all publishers before assertions.
4. Term::try_pid round-trips every issued boundary identifier. A value greater than M never reaches Term::pid, a live table entry, a body or a queue. Preserve the existing tagged-term and distribution wire formats; the separate u32 distribution refusal remains unchanged.

## R2 — Seal production registration and retain a fixture-only assigned-pid door

WHEN a process table registers a process, THE SYSTEM SHALL accept only a single-use reservation owned by that same allocator. It SHALL reject a foreign, replayed or invalid reservation by a named reason without replacing an entry. spawn_with_pid SHALL survive only under cfg(any(test, feature="test-support")); it SHALL NOT remain on the default production public surface. Its fixture use SHALL validate the identifier and SHALL NOT rewind allocator state or replace a live or retained identity.

Checklist: C57

Stories: S15

Acceptance:

1. Registry behavioral red at 753f66a24980e9314d6a0d47c7745e13ea90b2d9: use the existing spawn_with_pid(M+1) door and assert 0 inserted entries and no handle at M+1. The old registry.rs:69-71 inserts it. Capture the actual entry count, then clean up before the intended assertion; no Term::pid conversion, panic or missing-symbol failure is used as the red.
2. Registration consumes a same-allocator reservation once. A second registration using its recorded identity cannot replace the first handle; a foreign allocator reservation cannot enter this table. Assert exact named registration refusal, unchanged handle identity, unchanged table cardinality and 0 publication for each invalid attempt.
3. Compile a production-facing API fence without test-support proving the arbitrary-u64 spawn_with_pid door is absent. Separately compile/run the supported fixture door and its range/duplicate checks with test-support. The intentional API fence is structural evidence, not a substitute for the registry behavioral red.
4. Inventory and adapt every existing assigned-pid fixture and production registration call at the implementation head. Test seeding happens before issuance, is absent from production compilation and exposes no production reset or bypass. Reject unauthorized registration rather than silently accepting, overwriting or advancing a different allocator.

## R3 — Route every threaded issuer through the allocator after B-179 R1

WHEN a threaded spawn requests a pid, THE SYSTEM SHALL reserve through the domain allocator and propagate ExecError::PidSpaceExhausted through the fallible spawn surface established by B-179 R1. Exhaustion SHALL precede table/body/queue publication and lifecycle spawn notification. This requirement SHALL start only after B-179 R1 is qualified and landed and its owner releases the overlapping spawning.rs ownership. It SHALL preserve that requirement's terminal admission reservation and SHALL NOT redo its Result conversion or caller migration.

## R4 — Route cooperative root and deferred spawning through the same contract

WHEN a cooperative root or deferred spawn requests an identifier, THE SYSTEM SHALL use the same bounded, sticky-exhaustion contract and the same allocator authority as other issuers in that cooperative runtime. It SHALL replace saturating issuance and SHALL return a named exhaustion before appending deferred effects, creating a process or changing readiness. Native and bytecode roots SHALL NOT create separate overlapping counters.

## R5 — Preserve identity while terminal records and observers remain

WHILE a live handle, retained outcome, tombstone, monitor or exit/completion watch can name an issued pid, THE SYSTEM SHALL NOT issue that pid again. Monotonic never-recycle SHALL also hold after outcome consumption, bounded tombstone eviction and watcher drop. The allocator SHALL NOT add a second permanent pid-history ledger or require historical lookup on issuance. Existing terminal-record and watcher reclamation rules SHALL remain unchanged.

Checklist: C57

Stories: S15

Acceptance:

1. Create and exit a process, retain its real tombstone/outcome and an owned watch, then request subsequent pids: none equals the exited identifier. Repeat after outcome consumption, bounded tombstone eviction and watch drop; none is reused. Count issued identities and retained registrations, not elapsed time.
2. Use existing authoritative retained-outcome behavior (exit_tombstones.rs:62-87), not only the bounded 65536-entry compatibility map. Observe real watch registration/fire/drop (exit_events.rs:231-268), including multiple watchers and a concurrently finalized process. Each watch answers the original pid/reason once; no new process receives or impersonates that answer.
3. Production reset/reseed is absent. A new runtime owns a distinct allocator domain; old handles/watches remain bound to their old domain and cannot register or publish in the new one. A retired allocator cannot be reopened. Do not claim global or persisted pid uniqueness across independent runtimes or change a stored shape.
4. Count 0 history rows scanned, 0 tombstone/watch-list traversals during issuance, 0 whole-state clones, 0 added durable store calls and 0 added flushes. State the actual locks held and release them before user callbacks or await. Retain all existing watch/outcome pruning assertions; allocation adds only bounded allocator state/reservations.

## R6 — Propagate named exhaustion without remapping it to another failure

WHEN a spawn cannot reserve a pid, THE SYSTEM SHALL preserve a named PidSpaceExhausted refusal at each supported public/native boundary. ExecError::PidSpaceExhausted SHALL be a sibling of B-179's ExecError::SchedulerTerminated. The native SpawnError adapter SHALL preserve that reason, including the bytecode-visible named failure. THE SYSTEM SHALL NOT map pid exhaustion to badarg, noproc, an unresolved MFA, scheduler termination, a boolean success, a saturated pid or a placeholder.
